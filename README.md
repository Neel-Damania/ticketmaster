# Ticketing API

Spring Boot seat-reservation API backed by PostgreSQL and Spring Data JPA.

## Run locally

Run the launcher:

```bash
bash scripts/run-docker.sh
```

Or start Compose directly:

```bash
docker compose up --build
```

The API listens at `http://localhost:8080`; metrics are at `http://localhost:8080/actuator/prometheus`. Compose starts PostgreSQL and waits for it to become healthy before starting the application. The launcher supplies matching local database settings and generates a random JWT signing key when one isn't provided. Local database credentials remain development-only.

To run detached, pass Compose's `-d` option:

```bash
bash scripts/run-docker.sh -d
```

To customize local values, export them before running the script. For example:

```bash
export PORT=8090
export POSTGRES_DB=ticketmaster_dev
export POSTGRES_USER=ticketmaster
export POSTGRES_PASSWORD='choose-a-local-password'
export JWT_SECRET="$(openssl rand -hex 32)"
bash scripts/run-docker.sh
```

To run against an existing PostgreSQL database instead:

```bash
./mvnw spring-boot:run
```

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `SPRING_DATASOURCE_URL` | Launcher derives `jdbc:postgresql://db:5432/$POSTGRES_DB` | PostgreSQL connection URL from the app container |
| `SPRING_DATASOURCE_USERNAME` | `$POSTGRES_USER` | Database user used by the app |
| `SPRING_DATASOURCE_PASSWORD` | `$POSTGRES_PASSWORD` | Database password used by the app |
| `JWT_SECRET` | Random 32-byte secret generated by the launcher | JWT signing key; set a persistent strong secret when tokens must survive container restarts |
| `JWT_EXPIRATION_MS` | `3600000` | Token lifetime |
| `HOLD_TTL_SECONDS` | `300` | Seat-hold duration |
| `HOLD_SWEEP_INTERVAL_MS` | `5000` | Delay between expiry sweeps |
| `PORT` | `8080` | Published local port / platform port |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | `ticketmaster` | Local Compose PostgreSQL configuration |

## Health and metrics

- `GET /health/live` reports process liveness without contacting PostgreSQL.
- `GET /health/ready` checks PostgreSQL and returns `503` if it cannot be reached.
- `GET /actuator/prometheus` exposes Prometheus metrics, including confirmed reservations, reservation declines/replays, and the database-derived `seats_available{show_id="..."}` gauge.

Every HTTP response includes an `X-Request-ID`. A valid ID supplied in that header is propagated; otherwise the API generates one. Application request logs use JSON and do not include authentication tokens.

## Deployment status

`render.yaml` defines a Render Blueprint for the Dockerized API and managed PostgreSQL database. To deploy it, create a new Blueprint in Render from this repository and provide `SPRING_DATASOURCE_URL` when prompted. Set it to the database's internal address in JDBC form:

```text
jdbc:postgresql://<internal-host>:5432/ticketmaster
```

Render provides the database username and password and generates `JWT_SECRET`. The `/health/ready` endpoint is configured as the deployment health check. After deployment, add the assigned HTTPS address below:

```text
Live API: not deployed
```

Render's service logs are available in the service dashboard under **Logs**. They are not publicly accessible without dashboard access; capture and share the screen recording requested in `docs/Metrics.md` after deployment and load testing. Until a public deployment is created, local logs are available with `docker compose logs -f app`.
